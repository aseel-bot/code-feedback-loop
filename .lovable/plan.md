# خطة إكمال منصة عادل للسيارات

## ملاحظة على المكدّس التقني
المشروع الحالي مبني على TanStack Start (React + TypeScript + Tailwind) وهو المكدّس المدعوم هنا؛ لا يمكن التبديل إلى Next.js/NestJS. سأنفّذ نفس المتطلبات بمكافئاتها:

| المطلوب | البديل المنفَّذ |
|---|---|
| Next.js | TanStack Start (SSR + file routing) |
| NestJS API | Server Functions + مسارات `/api/*` |
| PostgreSQL + Prisma | Lovable Cloud (Postgres + RLS) |
| S3 + Presigned URLs | Lovable Cloud Storage |
| JWT auth للأدمن | Lovable Cloud Auth + RBAC عبر جدول `user_roles` |
| Redis/BullMQ | معالجة مباشرة داخل الـ handlers + جدولة عند الحاجة |
| reCAPTCHA v3 | reCAPTCHA v3 (يتطلب مفاتيح من المستخدم) |

## المرحلة 1 — الأساس والبيانات
- تفعيل Lovable Cloud وإنشاء المخطط: `cars`, `car_images`, `car_attributes` (سمات ديناميكية EAV), `brands`, `models`, `offers`, `services`, `posts`, `jobs`, `faqs`, `leads`, `service_bookings`, `job_applications`, `site_content`, `user_roles`.
- سياسات RLS: قراءة عامة للمحتوى المنشور، كتابة للأدمن فقط، إدخال Leads من الزوار عبر Server Function فقط.
- ترحيل البيانات الحالية من `src/data/site.ts` إلى قاعدة البيانات كبيانات أولية داخل الـ migration.
- نظام i18n: ملفات ترجمة `ar`/`en`، مسارات `/en/*`، تبديل `dir` تلقائي، إزالة كل النصوص المكتوبة مباشرة.

## المرحلة 2 — وحدة السيارات
- `/cars`: فلاتر كاملة (ماركة، موديل، فئة، سعر Range، سنة، وقود، ركاب، جير) داخل Modal مع تطبيق/إعادة تعيين، ترتيب رباعي، عداد "عرض X من أصل Y"، Pagination حقيقي.
- بطاقة السيارة: شارات ديناميكية، 5 مواصفات، السعر أو "احجز الآن"، القسط، زر مقارنة، Modal طلب شراء سريع.
- `/cars/{slug}`: معرض 5+ صور مع Lightbox/Zoom وسحب على الجوال، حاسبة تمويل تفاعلية (دفعة أولى + مدة 12–60 شهر) تمرّر القيم للنموذج، أقسام مواصفات من السمات الديناميكية، JSON-LD نوع Vehicle/Product، زر واتساب معبأ مسبقًا، رابط الطباعة.
- `/cars/{slug}/print` (إعادة توجيه 301 من المسار القديم `/cars/print`).
- `/cars/compare?ids=`: مقارنة 2–3 سيارات مع إزالة/استبدال.

## المرحلة 3 — وحدة الـ Leads
- Server Functions للتحقق الخلفي بـ Zod لكل النماذج + Rate Limiting بسيط على مستوى الطلب + reCAPTCHA v3.
- `/purchase/customers` و`/purchase/companies` (بريد، اسم شركة، سجل تجاري 10 أرقام) مع Autocomplete للسيارات.
- رقم مرجعي فوري + Toast + إرسال SMS/واتساب (يتطلب مفاتيح المزوّد؛ حتى توفرها يُسجَّل الطلب ويُعرض رقم الاتصال المباشر).
- `/contact-us` بأرقام مصنّفة حسب القسم، و`/services` مع نموذج حجز خدمة فعلي.

## المرحلة 4 — المحتوى
- توحيد `/offers` مع فلتر نوع العرض (عادي/ترويجي/موسمي) + عدّاد انتهاء + ربط العرض بالـ Lead، وإعادة توجيه 301 من `/promotional-offers`.
- المدونة: تصنيفات، بحث، ترقيم، SEO كامل، CTA وربط داخلي بالسيارات.
- `/about-us` بإحصاءات متحركة، `/faq` Accordion مُدار من الأدمن، `/jobs` مع رفع CV (PDF/Word ≤ 5MB).
- صفحة 404 مخصصة تعرض 4–6 سيارات مقترحة.

## المرحلة 5 — لوحة التحكم `/admin`
- تسجيل دخول + RBAC (مدير/مبيعات/محتوى) عبر جدول أدوار منفصل.
- CRUD: السيارات (مع رفع وترتيب الصور وتحرير السمات الديناميكية)، العروض، المدونة، الوظائف، الأسئلة، الخدمات، محتوى الصفحات.
- صندوق وارد موحّد للـ Leads: حالة (جديد/قيد المتابعة/مغلق)، تعيين موظف، سجل تواصل.
- تقارير: الأكثر مشاهدة/طلبًا، معدل التحويل، زمن الاستجابة، نقرات واتساب.

## المرحلة 6 — SEO والأداء والأمان
- Metadata فريدة لكل مسار (ar/en) + canonical + hreflang، `sitemap.xml` و`robots.txt` ديناميكيان.
- Slugs عربية نظيفة + جدول redirects لدعم 301 عند التغيير.
- صور متجاوبة srcset/sizes + WebP + lazy loading، استهداف LCP < 2.5s.
- مراجعة أمنية: تحقق خلفي شامل، تحديد المعدل، RLS، حماية XSS.

## المرحلة 7 — التحقق النهائي
مراجعة كل صفحة وفق معايير القبول: RTL/LTR، جوال/ديسكتوب، تحقق أمامي وخلفي، لا مفاتيح ترجمة ظاهرة، حماية النماذج، اختبار حالتي النجاح والفشل.

## ما أحتاجه منك
- مفاتيح reCAPTCHA v3 (Site + Secret).
- مزوّد SMS/واتساب وبياناته (أو نؤجل الإرسال ونكتفي بالتسجيل).
- ترجمة إنجليزية معتمدة للمحتوى أو الموافقة على ترجمة مبدئية أضعها أنا.

سأنفّذ المراحل بالترتيب وأقدّم تقريرًا بعد كل مرحلة.
